# Cybersecurity analysis engine (`POST /analyze`)

```
Node backend ──POST /analyze {url}──►  analysis/engine.py ──► normalized JSON report (schema_version 1.0)
                                          ├─ url_analysis        offline lexical checks
                                          ├─ homograph           punycode / mixed scripts / confusables
                                          ├─ typosquatting       Levenshtein + Jaro-Winkler + n-gram vs. 53 brands
                                          ├─ domain_analysis     DNS (A/AAAA/NS/MX) + RDAP registration (age, registrar)
                                          ├─ tls_analysis        certificate validity, issuer, expiry, hostname match, weak TLS
                                          ├─ website_analysis    static HTML inspection (forms, iframes, hidden items, scripts, redirects)
                                          ├─ brand_impersonation combines all of the above per brand
                                          ├─ threat_intelligence local heuristics + optional blocklist / DNSBL
                                          ├─ ml                  /predict model, when one is loaded
                                          └─ risk + recommendations
```

## Request / response
```bash
curl -s localhost:8000/analyze -H 'Content-Type: application/json' -H "X-API-Key: $ML_API_KEY" \
     -d '{"url":"https://paypa1-secure-login.xyz/verify","inspect_website":true,"include_ml":true}'
```
Top-level keys: `schema_version, engine_version, analyzed_at, duration_ms, url, modules, url_analysis, domain_analysis, tls_analysis,
website_analysis, typosquatting, homograph, brand_impersonation, threat_intelligence, reputation, ml, risk, recommendations, security_features`.

* `modules.<name>.status` is `ok | partial | failed | skipped` (+ `error` / `reason`). **A module that could not run is never reported as clean.**
* `risk.score` is 0-100, `risk.factors[]` lists every contributing finding with its points, `risk.method` is `heuristic` or `blended` (with ML).
* `ml` is `null` when no model is loaded; the rest of the report is unaffected.
* Validator: `analysis/schema.py::validate_report`. Real example reports: `backend/tests/fixtures/report.*.json` (generated by this engine).

## Safety model
| Concern | Control |
|---|---|
| SSRF | Only public IPs are contacted (loopback, private, link-local/cloud-metadata, CGNAT, reserved are refused). Checked on **every redirect hop**; decimal/hex/octal IP tricks are resolved before checking. |
| DNS rebinding | The connection goes to the IP that was validated, with the original `Host`/SNI. |
| Ports | Pages are fetched only on 80, 443, 8080, 8443, 8000, 8008, 8888 (no port scanning through the scanner). |
| Time | Per-request socket timeout + one wall-clock budget (`ANALYSIS_TOTAL_TIMEOUT`, default 20 s); slow-drip responses cannot outlive it. |
| Size | HTML capped at 1 MB; gzip/deflate output is capped too (decompression bombs). |
| Execution | HTML is parsed as text only. No JavaScript runs, nothing is rendered, **downloads are never read** (only headers recorded). |
| Abuse of the service | API key, concurrency cap (HTTP 429), inputs validated, full URLs never logged (host only). |

## Risk scoring
Additive and fully traceable (see `analysis/risk.py`). The weights are **expert heuristics, not learned or validated**:
evaluate and tune them on labelled data before relying on the score. Specific evidence (blocklist hit, strong brand impersonation) is
never offset by "old domain" / "valid TLS" mitigations; a domain that officially belongs to a listed brand is capped at 10.

## Known limitations
* RDAP gives age only for TLDs with a public RDAP server; otherwise age is `null` (module `partial`).
* No reputation feed needing API keys is built in (Google Safe Browsing, VirusTotal...). `DNSBL_ZONES` and `BLOCKLIST_PATH` are optional hooks.
* Brand list (53 brands) and keyword lists are hand-curated; extend `analysis/data/brands.json` for your market.
* Static inspection cannot see content rendered by JavaScript or cloaked from scanners. Phishing kits often hide from bots.
* Registered-domain parsing uses a short suffix list; use the Public Suffix List for production accuracy.
